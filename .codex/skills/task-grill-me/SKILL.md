# Employee All Task Grill Me

在编码前把模糊需求整理成可验证、可估算的前后端任务。Skill 从 `employee-all` 根目录运行，覆盖 `employee-web/` 和 `spring-boot-demo/`，文档写入根目录下的 `docs/`。本 Skill 只分析和落盘，不修改业务代码、不创建分支、不提交代码。

## 输入与目录

- 接受任务号、需求标题、需求文档或用户描述。
- 有任务号时使用该编号；没有时生成简短的小写连字符标识，并在输出前告知用户。
- 默认输出：`docs/grill/{task-id}/task-effort-estimate.md`。
- Jira、GitHub Issue 或其他外部系统只是可选事实源。只有工具可用且用户要求时才读取或写入；不得因连接器缺失阻塞本地分析。

## 工作流

### 1. 收集事实

读取用户描述、附件和本地文档。按需求检查 `employee-web/` 的 Vue 组件、请求与构建配置，以及 `spring-boot-demo/` 的 Maven 配置、Spring 分层、数据访问、缓存和测试，确认：

- 用户目标与验收结果。
- 范围内和范围外。
- 涉及的页面、组件、状态、接口和浏览器尺寸。
- 是否影响接口、权限、MySQL、Redis、路由或前后端构建配置。
- 当前代码已有能力和可复用实现。

事实不足且会改变范围或估算时再提问，不用问题替代可以完成的代码检索。

### 2. Grill 访谈

- 一次只问一个问题。
- 给出推荐答案及理由，同时允许用户直接修正。
- 优先确认范围、交互状态、接口契约、兼容性、验收方式和测试要求。
- 只把用户明确确认的答案写成需求事实；推荐项和推测保持为待确认。
- 当用户确认共同理解，或明确要求开始估算时结束访谈。

### 3. 代码影响分析

优先使用 `rg` 定位候选代码，再读取相关文件。至少判断：

- 页面、组件、状态、请求、错误处理及桌面/移动端布局。
- Controller、Service、Repository、Entity 和 DTO 的职责与调用链。
- API 路径、请求参数和响应结构。
- MySQL 表、索引、事务及 Redis 缓存键、TTL 和失效策略。
- `employee-web/package.json` 与 `spring-boot-demo/pom.xml` 中实际可用的构建和测试方式。

区分“代码确认事实”和“待验证推断”，并给出相对 `employee-all` 根目录的文件路径证据，例如 `employee-web/src/App.vue` 或 `spring-boot-demo/src/main/java/...`。

### 4. 拆分与估算

- 每个任务为 `0.5d`、`1d`、`1.5d` 或 `2d`。
- 超过 `2d` 必须继续拆分；小于 `0.5d` 的相关工作合并处理。
- 每个任务必须有目标、候选文件、交付物、依赖、验收条件和最小验证方式。
- 页面实现、接口联调、测试验证可以分开，但不得拆成无法独立验证的机械步骤。
- 不把范围外事项计入工时。

分别汇总开发、自测/联调和风险缓冲。只有存在真实不确定性时才加入缓冲并说明原因。

### 5. 输出

按以下结构生成 `task-effort-estimate.md`：

## 需求事实来源
## Grill 访谈结论
## 范围内
## 范围外
## 关键假设

## 子任务拆分
| Task | 标题 | 候选文件 | 工作内容 | 交付物 | 估时 | 依赖 | 验收与验证 | 风险 |

## 外部任务系统

只有用户明确要求创建外部任务，且相应工具可用时才执行：

1. 先展示待创建任务、父任务、类型、工时和重复项判断。
2. 在实际写入前取得用户最终确认。
3. 不猜测项目、负责人、优先级或必填字段。
4. 逐条记录成功、跳过和失败结果。

## 质量门禁

- 已确认边界没有被遗漏或扩大。
- 每个任务都在 `0.5d` 到 `2d`。
- 代码影响面有实际路径证据。
- 验证方式具体到页面、接口、构建命令或浏览器尺寸。
- 外部写入未经用户确认不得执行。

完成后简要报告文档路径、总工时、置信度和最主要风险。
